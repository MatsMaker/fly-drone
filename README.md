## Фізична модель

Дрон рухається лише силами й моментами, швидкість ніде не задається напряму.

- **Тяга** вздовж локальної осі Y, максимум `m·g·TWR` (TWR = 2.5).
- **Опір повітря** квадратичний і анізотропний: `F = −½·ρ·Cd·A·v·|v|` окремо по кожній локальній осі (площа зверху 0.06 м², спереду 0.03 м²).
- **Stabilized:** PD-регулятор тримає цільовий кут нахилу (помилка рахується через кватерніони), PI-регулятор — вертикальну швидкість; тяга компенсує нахил діленням на cos.
- **Acro:** P-регулятор кутової швидкості, як у FPV-прошивках.

Перевірка розрахунком: гранична швидкість вільного падіння `√(m·g / k) ≈ 16 м/с` — підтверджується PlayMode-тестом.

## Світ і стрімінг

- Світ 8×8 км із тайлів 1×1 км, рельєф — fBm + ridged noise з domain warping, детермінований за seed.
- Навколо дрона — квадрат 5×5 тайлів; вивантаження з гістерезисом (радіус 3), щоб тайли не «блимали» на межі.
- Висоти, splat-карти й дерева рахуються у фонових потоках (`Task.Run`), застосування — не більше одного тайла на кадр.
- Terrain-об'єкти перевикористовуються з пулу; `TerrainData` явно знищується при вивантаженні.
- Floating origin зсуває світ кожні 2 км, щоб уникнути втрати точності float.

## Обмеження й наступні кроки

- Стрімінг через `Task.Run`; наступний крок — Jobs + Burst для генерації і пул масивів, щоб прибрати алокації.
- Немає трави (detail objects) — навмисно, заради часу.
- Дерева без білбордів на відстані — їх дає SpeedTree або імпостери.
- Floating origin може дати стрибок інтерполяції на один кадр у момент зсуву.
- Вітер і турбулентність — найпростіше розширення фізичної моделі.
